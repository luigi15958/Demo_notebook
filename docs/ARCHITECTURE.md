# מחברת החונכות האישית — ארכיטקטורה

מסמך זה מתאר את הארכיטקטורה המוצעת לאפליקציה, בהתאם לדף החזון ([VISION.md](VISION.md)).
אבטחת מידע, תשתית ותהליכי תחילת השנה (הזדהות כפולה, שרת ייעודי, ייבוא ושיוך) מפורטים
ב-[SECURITY.md](SECURITY.md).

## 1. עקרונות ארכיטקטוניים

1. **פרטיות by design** — מדובר במידע רגיש על קטינים. ברירת המחדל: רשומת חונכות שייכת לחונכ.ת ואינה נראית לאיש; חשיפה מערכתית היא מטא-דאטה בלבד (התקיים/תועד), ותוכן משותף רק בפעולת שיתוף מפורשת ומתועדת.
2. **Mobile-first, עברית, RTL** — התיעוד קורה בין מפגשים, מהטלפון, בדקות בודדות.
3. **Offline-friendly** — תיעוד מפגש חייב לעבוד גם כשאין רשת יציבה (PWA עם סנכרון).
4. **פשטות תפעולית** — בית ספר, לא סטארטאפ: מינימום רכיבי תשתית, גיבוי אוטומטי, עלות תחזוקה נמוכה.
5. **שנת לימודים כציר** — כל הנתונים מעוגנים בשנה"ל; מעבר שנה הוא תהליך מובנה (שיבוץ מחדש, העברת תקציר).

## 2. סקירה כללית

```
┌────────────────────────────────────────────────────┐
│                 לקוח: PWA (React, RTL)             │
│  אפליקציית חונכ.ת │ לוח רכזת │ ניהול │ ספרייה      │
└──────────────────────────┬─────────────────────────┘
                           │ HTTPS / REST (JSON)
┌──────────────────────────┴─────────────────────────┐
│                שרת API (Node.js + NestJS)          │
│  Auth & RBAC │ שירותי דומיין │ שיתופים │ התרעות    │
│  Audit Log   │ מנוע תזכורות (cron) │ ייצוא/גיבוי   │
└───────┬──────────────────┬─────────────────────────┘
        │                  │
┌───────┴────────┐  ┌──────┴───────────┐
│  PostgreSQL    │  │  Object Storage  │
│  (הצפנה at     │  │  (קבצי ספרייה,   │
│   rest, RLS)   │  │   דפי מידע)      │
└────────────────┘  └──────────────────┘
```

**סטאק (הוכרע):** React + TypeScript (Vite, PWA) בצד לקוח; **Supabase** כפלטפורמת שרת — Postgres + Auth + Row-Level Security + Storage + Edge Functions. הלוגיקה העסקית ממומשת ב-RLS ובפונקציות; אין שרת ייעודי לתחזק. אם בעתיד יידרש שרת מלא (NestJS), שכבת הגישה לנתונים בלקוח בנויה כ-Repository מוחלף.

## 3. תפקידים והרשאות (RBAC)

| תפקיד | רואה | כותב |
|---|---|---|
| חונכ.ת | החניכים שלה בלבד: תיק ילד, תיעודים שלה, תקצירים שהועברו אליה, ספרייה | תיעוד מפגשים, מטרות, יומן קשר, הפניות, רפלקציה אישית |
| רכזת חונכות | מטא-דאטה מערכתי (כיסוי, סטטוסים), הפניות שהופנו אליה, שיבוצים, ספרייה | שיבוץ חונכים, מחזורי הערכה, הדרכות, תוכן ספרייה, התרעות |
| יועצת | הפניות ושיתופים שהופנו אליה במפורש בלבד | תגובה להפניות, תיעוד ליווי לחונכת |
| הנהלה | דוחות מצרפיים אנונימיים ברמת חטיבה | — |
| מנהל מערכת | ניהול משתמשים, שנים, גיבויים (ללא גישת תוכן) | הגדרות |

- **אכיפה בשתי שכבות**: בדיקת הרשאות בשכבת השירות + Row-Level Security ב-Postgres (מגן גם מפני באג בשרת).
- **Audit log** בלתי-ניתן-לעריכה על כל צפייה/שינוי ברשומות רגישות.
- הזדהות: אימייל + סיסמה או SSO של Google Workspace הבית-ספרי; 2FA לבעלי תפקידים מערכתיים.

## 4. מודל הנתונים (ישויות מרכזיות)

```
SchoolYear (שנת לימודים)
 ├── User (משתמש: חונכת/רכזת/יועצת/מנהל) ── Role
 ├── Student (חניכ.ה: פרטים, חטיבה)
 │     ├── StrengthProfile (חוזקות — מתעדכן לאורך השנה)
 │     └── IntakeInfo (תיק היכרות: מידע מיועצת/חונך קודם/הורים)
 ├── Mentorship (שיבוץ חונכת↔חניכ.ה לשנה; סטטוס)
 │     ├── Meeting (מפגש: תאריך, משך, נושאים, being/doing,
 │     │            חוזקות ואתגרים, דרכי פעולה, תובנות)
 │     ├── Goal (מטרה: תחום [לימודי/חברתי/אישי/רגשי],
 │     │         סטטוס, אבני דרך, קישור למפגשים)
 │     ├── ContactLog (יומן קשר: הורה/מורה/יועצת; ערוץ; תוכן)
 │     ├── TriangleMeeting (פגישה משולשת: משתתפים, סיכומים)
 │     ├── Evaluation (הערכה: אמצע/סוף שנה; משוב דיאלוגי)
 │     ├── YearSummary + HandoverBrief (סיכום שנה + תקציר העברה)
 │     └── TimelineEvent (נגזר: ציר הזמן החונכותי)
 ├── Referral (הפניה: עץ סיוע / ועדת פתרון סכסוכים;
 │             נמען, סטטוס, חתימת חונך.ת, שרשור תגובות)
 ├── MentorSelection (תהליך בחירה: דירוגי תלמידים, שיבוץ)
 ├── MentorReflection (רפלקציית חונכ.ת: גלגל החונך, תבחינים — פרטי לחלוטין)
 ├── LibraryItem (ספרייה: מאמר/משחק/מערך שיחה/דף מידע; תגיות)
 ├── TrainingSession (הדרכות: מועדים, נוכחות, בקשות ליווי)
 └── Notification / ReminderRule (התרעות ותזכורות)
```

הערות מודל:
- **Meeting.content** נשמר כטקסט חופשי + שדות מובנים אופציונליים — התבנית מהחוברת היא scaffold, לא חובה.
- **שיתוף** (Share) הוא ישות נפרדת: רשומה משותפת מפנה למקור עם snapshot, נמען, סיבה וחותמת זמן — כך יש שליטה ושקיפות מלאה על כל חשיפת מידע.
- **HandoverBrief** הוא מסמך שהחונכת מרכיבה בסוף שנה; המחברת המלאה לא עוברת אוטומטית.

## 5. מודולים פונקציונליים

1. **הילדים שלי** — רשימת חניכים, כרטיס ילד.ה (חוזקות, מטרות, ציר זמן, יומן קשר, תיק היכרות).
2. **מפגשים** — מסך "לקראת המפגש" (הקשר מרוכז), תיעוד מהיר, היסטוריה, מדד איזון being/doing.
3. **מטרות והערכה** — הגדרת מטרות, מעקב, מחזורי הערכה אמצע/סוף שנה, סיכום שנה.
4. **משולש התקשורת** — יומן קשר הורים וצוות, פגישות משולשות, תיאום ציפיות.
5. **עץ קבלת סיוע והפניות** — אשף "למי פונים", טופס ועדת פתרון סכסוכים, מעקב סטטוס.
6. **ספריית החונכות** — תכני החוברת כפרקים חיים, רעיונות לפעילויות (עם סינון לפי מטרה/גיל), דפי מידע לאירועי שנה, העלאת תכנים ע"י הצוות.
7. **המרחב שלי (חונכ.ת)** — רפלקציה אישית, גלגל החונך, בקשות ליווי, הדרכות.
8. **לוח הרכזת** — כיסוי ותיעוד (מטא-דאטה), תהליך בחירת חונכים ושיבוץ, ניהול מחזורי הערכה והדרכות, התרעות.
9. **ניהול** — משתמשים, שנת לימודים, פתיחת/סגירת שנה, ייצוא וגיבוי.

## 6. חתכים רוחביים

- **מנוע תזכורות**: כלל-מבוסס (cron בשרת) — מפגש שלא תועד, פער מפגשים, יום הולדת, מעקב דרך פעולה, הערכה מתקרבת. התראות push (PWA) + סיכום שבועי.
- **חיפוש**: חיפוש טקסט מלא (Postgres FTS עם תמיכה בעברית) בתוך הרשומות של המשתמש בלבד.
- **ייצוא**: PDF לסיכום שנה/תקציר העברה; ייצוא מלא למנהל מערכת לצורכי גיבוי.
- **נגישות**: עמידה בתקן ישראלי 5568 / WCAG 2.1 AA.

## 7. אבטחה ופרטיות

- הצפנה בתעבורה (TLS) ובמנוחה; שדות רגישים במיוחד (תוכן מפגשים, תיק היכרות) מוצפנים ברמת השדה.
- עמידה בחוק הגנת הפרטיות ותקנות אבטחת מידע (מאגר מידע רגיש על קטינים): מזעור נתונים, הגדרת מורשי גישה, תיעוד גישה, נוהל מחיקה בסיום לימודים.
- אין שימוש בנתונים לאימון מודלים; אין אנליטיקה צד-שלישי על תוכן.
- מדיניות שמירה: נתוני חונכות נשמרים X שנים (להגדרת בית הספר) ואז נמחקים/מאונמים.

## 9. הכרעות (התקבלו מול בית הספר)

1. **אירוח: Supabase** — ענן מנוהל עם Postgres, Auth, RLS, Storage וגיבויים אוטומטיים. עלות נמוכה, תחזוקה מינימלית, ואפשרות הגירה עתידית (Postgres סטנדרטי).
2. **נתוני תלמידים: הזנה ידנית + ייבוא CSV** — הרכזת מזינה או מייבאת קובץ תלמידים/שיבוצים בתחילת שנה. ללא תלות במערכות חיצוניות; ממשק למשו"ב יישקל בעתיד אם יעלה צורך.
3. **מקרי קיצון: מנגנון "שבירת זכוכית"** — יועצת ומנהל **יחד** יכולים לפתוח רשומת חונכות ללא הסכמת החונכת, רק בצירוף סיבה מתועדת. החונכת מקבלת הודעה אוטומטית, והפעולה נרשמת ביומן ביקורת גלוי. בכל מצב אחר — תוכן נחשף רק בשיתוף מפורש של החונכת.
4. **הורים ותלמידים: לא משתמשים במערכת** — המערכת היא כלי פנימי לצוות. הקשר עם הורים ותלמידים מתקיים בערוצים האישיים ומתועד במערכת בלבד. ההחלטה תיבחן מחדש רק לאחר שימוש יציב של שנה ומעלה.
