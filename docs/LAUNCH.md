# מדריך השקה — העלאת מחברת החונכות לאוויר

תהליך של כ-30–40 דקות מול מחשב, פעם אחת. בסופו: כתובת אינטרנט אמיתית עם
בסיס נתונים מאובטח, כניסה אישית לכל חונכ.ת, וכל ההרשאות נאכפות בשרת.

## שלב 1: פתיחת פרויקט Supabase (~10 דק')

1. נכנסים ל-supabase.com → **Start your project** → הרשמה (רצוי עם חשבון Google של בית הספר).
2. **New project**:
   - שם: `mentoring-notebook`
   - **Region: Europe (Frankfurt) — eu-central-1**
   - Database Password: סיסמה חזקה → **לשמור במקום בטוח** (זו סיסמת העל של בסיס הנתונים).
3. ממתינים ~2 דקות שהפרויקט יעלה.

## שלב 2: הקמת בסיס הנתונים (~5 דק')

1. בתפריט הצד: **SQL Editor** → New query.
2. מדביקים את כל התוכן של הקובץ [`supabase/setup_all.sql`](../supabase/setup_all.sql) → **Run**.
   (זה מריץ את כל המיגרציות 0001–0006 בבת אחת: טבלאות, הרשאות RLS, פונקציות.)
3. מעדכנים את קוד הפתקים — מריצים ב-SQL Editor (מחליפים לקוד שתבחרו):
   ```sql
   update app_settings set value = 'הקוד-שבחרתם' where key = 'note_access_code';
   ```

## שלב 3: הגדרות אבטחה ב-Supabase (~5 דק')

ב-**Authentication → Sign In / Up**:
- **Allow new users to sign up: כיבוי** (חשבונות רק בהזמנה).
- Minimum password length: **12**.
- **Prevent use of leaked passwords: הפעלה** (בדיקה מול מאגר דליפות).

ב-**Authentication → URL Configuration**:
- Site URL: כתובת האפליקציה (שלב 5).

## שלב 4: מה לשלוח לי בצ'אט

מ-**Settings → API** בפרויקט:
1. **Project URL** (נראה כמו `https://xxxx.supabase.co`)
2. **anon public key** (המפתח הציבורי — בטוח לשיתוף; הוא ממילא מוטמע באפליקציה)

⚠️ **לא לשלוח** את ה-`service_role key` ולא את סיסמת בסיס הנתונים — לאף אחד, כולל לי.

## שלב 5: חיבור האתר (~5 דק', בגיטהאב)

1. **הפעלת Pages** (הצעד החד-פעמי): github.com/luigi15958/Demo_notebook → Settings → Pages → Source: **GitHub Actions**.
2. **הזנת המפתחות**: Settings → Secrets and variables → **Actions** → לשונית **Variables** → New repository variable:
   - `VITE_SUPABASE_URL` = ה-Project URL
   - `VITE_SUPABASE_ANON_KEY` = ה-anon key
3. אחרי ששולחים לי — אני מריץ פריסה מחדש, והאתר `https://luigi15958.github.io/Demo_notebook/` הופך למערכת האמיתית (מסך כניסה עם מייל+סיסמה במקום מצב ההדגמה).

## שלב 6: יצירת המשתמשים הראשונים (~5 דק')

ב-**Authentication → Users → Invite user**: מזינים את המייל הארגוני של כל איש.ת צוות.
כל מוזמנ.ת מקבל.ת מייל וקובע.ת סיסמה — ואז מריצים עבורם שורת שיוך פרופיל ב-SQL Editor
(אכין לך את השורות המדויקות ברגע שתשלח את רשימת הצוות: שם, מייל, תפקיד, חטיבה).

## שלב 7: בדיקת עשן משותפת

נעבור יחד: כניסה כרכזת → ייבוא ילדים → נעילת/פתיחת שיבוץ → כניסה כחונכ.ת →
בחירת חניכים → תיעוד מפגש → פתק ממורה (עם הקוד החדש) → בדיקה שהכול נשמר.

## מה נשאר לשלב הבא (אחרי ההשקה)
- אכיפת דומיין ארגוני בטריגר (שלב ב' במסמך האבטחה) — צריך לדעת את הדומיין שלכם.
- MFA (אימות דו-שלבי) — שלב ג'.
- יומן ביקורת ושבירת זכוכית — שלב ד'.
- ההדגמה הציבורית (githack) ממשיכה לחיות בנפרד עם נתונים בדויים.
